## Подтверждённые дефекты (аудит, часть 2, 2026-11-18)

### C-6. `NexxusTreasuryVesting.fc` — любой может вывести казну

- В `OP_RELEASE_VESTING_BATCH` **нет проверки отправителя** (сравнения с
  `epoch_controller` нет, в отличие от `OP_NOTIFY_EPOCH_REWARDS`).
- `batch_earned_ts` и `batch_amount` берутся из сообщения; `batch_id`
  считывается, но **нигде не фиксируется** → повторный запрос не блокируется.
  Отправка `ts = 0`, `amount = locked_vesting` выводит весь казна-вестинг.
- `batches_dict` объявлен, загружается и сохраняется, но **не читается и не
  пишется** (нет ни `udict_set`, ни проверки батча).
- Сообщение Jetton собрано неверно: сумма пишется как `uint128` вместо
  `coins`, отсутствуют `destination`, `response_destination`,
  `forward_ton_amount`.
- Режим отправки `1` тратит 0,1 TON с баланса контракта на каждый вызов, без
  резерва на storage fee.
- Комментарий «mint_msg» не соответствует коду (это transfer, не mint).

### C-7. `NexxusEpochController.fc` — проверка кворума фиктивна

- Проверка подписи: `throw_unless(ERROR_INVALID_BLS_QUORUM, signature_hash > 0)`.
  Это проверка «число больше нуля», а не подписи. `auditor_bls_pubkey` из
  хранилища **не используется вообще**.
- `OP_UPDATE_AUDITOR_SET` (0x7e1a0002) и `OP_SUBMIT_POR_PROOF` (0x7e1a0003)
  объявлены, но обработчиков нет → уходят в `throw(0xffff)`.
- Операции, обновляющей `total_nodes` / `total_bond_nanotons`, нет: условие
  «не менее 100 узлов» недостижимо легитимным путём.
- Конфликт дизайна: контракт завязан на BLS-12-381, а нода и ADR-0008
  используют **Ed25519 M-of-N**. Это два несовместимых дизайна.

### C-8. `NexxusAuditorCouncilBond.fc` — залог не привязан к адресу

- `OP_DEPOSIT_BOND` увеличивает только `total_bonded_tons` и
  `active_auditors_count`; `auditor_bonds_dict` не используется → один адрес
  может внести минимальный залог много раз и «стать» несколькими аудиторами.
- `OP_WITHDRAW_BOND` объявлен, но обработчика нет → `throw(0xffff)`; вывода
  залога не существует.
- Slashing уменьшает счётчики, но **не двигает средства** и не привязан к
  адресу аудитора.
- Вся власть — у одного ключа `admin`.

## Что делать при переписывании

1. Хранить per-address учёт: словарь по адресу владельца и отдельный словарь
   по `batch_id` (залог, батчи, мандаты).
2. Проверять отправителя на каждой операции (`equal_slices` с адресом из
   хранилища) и проверять уникальность `batch_id`/идентификатора залога.
3. Настоящая проверка подписей: в TVM есть `check_signature` для Ed25519 —
   это согласуется с дизайном ноды (ADR-0008) и снимает конфликт с BLS.
4. Тесты на атаки: вывод казны, повторный выпуск батча, поддельная подпись,
   двойной депозит с одного адреса, slashing без залога.
5. Сборка: Tolk или FunC + Blueprint + Sandbox; контрактные тесты — в CI.
6. Только после этого — внешний аудит контрактов.
